ConnectUni Backend — Implementation Report
==========================================


OVERVIEW
--------
A FastAPI async backend for a university mentorship and community platform. Built with
PostgreSQL + SQLAlchemy async (aiosqlite for tests), Cloudinary for media storage, SMTP
email with HTML templates, JWT authentication with token rotation, and WebSockets for
real-time features.


AUTHENTICATION & SECURITY
--------------------------
Endpoints (/auth)

  Method  Path                    Purpose
  ------  ----                    -------
  POST    /auth/register          Register new user (STUDENT / PROFESSIONAL / ALUMNI)
  GET     /auth/verify-email      Verify email via token link
  POST    /auth/login             Login -> access + refresh tokens
  POST    /auth/logout            Revoke refresh token
  POST    /auth/refresh           Issue new tokens (rotation — each refresh token single-use)
  POST    /auth/forgot-password   Request password reset
  POST    /auth/reset-password    Reset password with token
  GET     /auth/users             Dev utility: paginated user list

Key implementation details:
- Argon2 password hashing
- JWT access tokens (15-minute expiry) + refresh tokens (14-day, SHA256-hashed in DB)
- Token rotation — refresh token is revoked and reissued on every use
- .ac.uk student accounts are automatically set to VERIFIED status on email confirmation
- Professionals marked SELF_DECLARED at registration
- Password reset tokens expire after 30 minutes
- Email-enumeration-safe forgot-password response (same message whether email exists or not)


PROFILE SYSTEM
--------------
Endpoints (/profiles, /profile)

  Method  Path                          Purpose
  ------  ----                          -------
  POST    /profiles/                    Create base profile
  GET     /profiles/me                  Get own profile
  GET     /profiles/{user_id}           Get any user's profile (public, no auth)
  PATCH   /profiles/me                  Update profile fields
  PUT     /profiles/me/avatar           Upload / replace avatar (Cloudinary)
  GET     /profiles/me/completion       Completion % + list of missing fields
  POST    /profile/student              Create / update student role profile
  POST    /profile/alumni               Create / update alumni profile (with certificate upload)
  POST    /profile/professional         Create / update professional profile
  POST    /profile/mentorship/prefs     Set mentorship preferences
  GET     /profile/me                   Full combined profile (all role data)
  PUT     /profile/{user_id}/verify     Admin: update verification status

Role-based profile models:
- StudentProfile    — major, graduation year, interests
- AlumniProfile     — course completed, graduation year, certificate URL
- ProfessionalProfile — job title, company, years of experience, skills

Verification status flow:
  UNVERIFIED -> (email click for .ac.uk) -> VERIFIED
             -> (admin action)           -> VERIFIED / PENDING


EVENT SYSTEM
------------
Endpoints (/events)

  Method  Path                    Purpose
  ------  ----                    -------
  GET     /events/                Upcoming events (filterable by type)
  GET     /events/past            Past events
  GET     /events/rsvps           Current user's RSVPs
  GET     /events/{id}            Single event detail
  POST    /events/                Create event (multipart, optional cover image)
  PATCH   /events/{id}            Update event (organiser only)
  PUT     /events/{id}/cover-image Upload / replace cover image
  POST    /events/{id}/rsvp       RSVP (sends confirmation email in background)
  DELETE  /events/{id}/rsvp       Cancel RSVP

Guards:
- Organiser cannot RSVP to their own event
- Cannot RSVP to a past event
- Cannot create two events on the same date (409)
- Duplicate RSVP blocked with SELECT FOR UPDATE (race-condition safe, 409)
- Capacity limit enforced atomically in the repository

overlapping skills, goals, preferred format, and availability.

Rich list responses — mentor/mentee lists include progress percentage, next upcoming
session, and milestone summary.

REAL-TIME (WEBSOCKETS)
----------------------
Two WebSocket channels:

- /notifications/ws?token=<JWT>
  Personal notification stream per user. Verifies JWT on connect, broadcasts to that
  user's active connections, handles client pings.

- /communities/{id}/ws?token=<JWT>
  Community chat room. Verifies membership before allowing connection, broadcasts to all
  members in the room, handles connection pooling.


FILE UPLOADS (CLOUDINARY)
-------------------------
All file handling goes through ImageService with:
- Magic-byte signature validation (not just MIME type)
- Size limits by context: avatars 5 MB, all others 10 MB
- Organised cloud folders by upload type
- Old file deletion on replace

Upload contexts supported:
- User avatars
- Event cover images
- Community cover images
- Community message attachments
- Alumni certificates
- Mentorship request attachments


EMAIL SYSTEM
------------
HTML email templates (16 KB template file) covering:

- Welcome + email verification on registration
- Password reset
- RSVP confirmation
- Mentorship: request received, accepted, rejected, cancelled, relationship ended
- Milestone completed
- Session cancelled
- Resource shared
- Certificate received, verification status updated, preferences saved

All emails sent via FastAPI BackgroundTasks (non-blocking — no user-facing latency).

INFRASTRUCTURE
--------------
Database
- PostgreSQL 16 (production) via asyncpg
- SQLite + aiosqlite for tests (in-memory, session-scoped)
- Connection pool: pool_size=20, max_overflow=20

Docker Compose
- db       — PostgreSQL 16
- api      — FastAPI + Uvicorn (volume-mounted for dev)
- pgadmin  — PgAdmin on port 5050 (credentials from .env)

CI/CD (GitHub Actions)
- Triggers on push to main
- SSH into EC2 via appleboy/ssh-action
- git reset --hard origin/main -> docker compose up --build -d -> alembic upgrade head -> restart

CORS
- CloudFront CDN domain + localhost:5173 (Vite dev server)
